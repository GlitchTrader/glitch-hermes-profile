# Geometry and scheduled decision tools — v0.0.2.78

## Bounded correction

The existing wording allowed a nearby pivot to be called noise-surviving without
distinguishing ordinary retest movement from thesis failure. Entry reasoning now
names that distinction in its existing geometry field. The failure boundary is
selected before optimizing entry risk; anticipation and genuinely local setups
remain available. No dollar, ATR, reward/risk or confirmation gate is added.

Native initial protection has an existing fill-relative-offset contract. The
geometry context and doctrine now state it explicitly, including entry-range
translation and possible slippage. Native order prices, sizing, protection,
replication and validation are not changed to fit a model's contrary assumption.

The fully supplied scheduled decision used a general toolset, allowing arithmetic
tool attempts that unattended approval would block. Its subprocess now registers
and selects an explicitly empty toolset through the public Hermes API. Charts,
preloaded skills, current evidence and deterministic arithmetic handling remain.
There is no approval relaxation, core Hermes patch or persistent tool/config edit.
Learner and interactive capabilities are unchanged.

The distribution ownership list names its nine Glitch skill directories rather
than the shared skills root. Supported updates therefore preserve unrelated
bundled/user skills and root usage metadata instead of replacing that folder.

Carried plans retain continuity, but prior probability/robustness prose is not new
confirmation; those assessments must use current evidence. This does not establish
a time-dependent degradation mechanism, calibrated edge or profitable outcome.

Separately, the learner collector repeated full directory enumeration and prior
plan searches before checking whether an episode was already recorded or eligible.
This redundant computation grows with retained history. It now indexes frames once
per pass, skips recorded intents before expensive reconstruction, and loads prior
cognition only for an eligible new record. Five subsequent frames are selected
with the same strict chronological boundary; new arrivals remain eligible on the
next pass. Learning records, grouping, rebuild behavior and model rules are kept.
The computational defect is not proof it caused a particular trading loss.

## Proof and protected behavior

- Regression coverage explains long/short fill translation and absent references
  without mutating inputs or selecting an action.
- Subprocess tests cover flat, triggered and positioned decisions while preserving
  model, reasoning, preloaded skills, image and prompt transport.
- Existing prompt-budget, anticipatory-entry, no-fixed-strategy, output correction,
  delivery, position management and learning contracts remain required.
- Full profile regression: 493 tests passed. The installed Hermes API resolves
  the registered empty toolset to zero model tools in an offline compatibility
  check. These are source/API checks, not a claim of live trading acceptance.
- Collector tests preserve existing records, per-instrument attribution, one
  frame enumeration per pass, and deferred eligibility for incomplete evidence.
  An offline frozen-corpus comparison additionally requires identical old/new
  derived records, including new episodes, with writes captured in memory only.
- No changes to native code, account configuration, model/cadence, learned-state
  lifecycle, execution admission or authored probability/price validation.

Deployment and private runtime evidence are recorded outside this public repository.
Source tests alone do not prove installed behavior or trading performance.

# Maintenance output contract - v0.0.2.80

The review found three output-contract problems, not grounds for another strategy
or risk calibration:

- The setup-deferral check matched ordinary statements that price had not
  supplied a market response. It now binds missing-supply language to an
  explicitly absent geometry field. Deferring objective/invalidation derivation
  to the packet still fails; describing absent acceptance does not.
- A management decision could name a stop move in prose while omitting the
  executable protection payload. The position-only prompt now supplies compact
  action-specific payload shapes beside each ordered book's deduplicated native
  leg identities. Examples do not choose actions, prices or affected legs.
  Missing, foreign or placeholder legs remain invalid; no repair fabricates a
  protection request from prose.
- An existing arithmetic correction returned dollars where the verdict enum
  belonged. When the validator supplies an exact expected verdict, its existing
  correction prompt now names that literal field. Arithmetic checks, probability
  estimates, action-preserving repair boundaries and the one-repair limit remain
  unchanged.

Protected: SOUL, trading skills, entry ranges, probability/EV requirements,
invalidation semantics, native fill-relative brackets, protection/execution,
replication, compliance, learner promotion, model, cadence, market/freshness/AI
admission and retained runtime evidence. No NinjaTrader source changes belong to
this release.

Regression coverage includes the observed false-positive language, genuine
geometry deferral, book isolation, duplicate/missing/malformed native protection,
placeholder rejection, strict management math, unchanged flat prompt and full
profile tests. Private raw executions, decisions and deployment receipts stay
outside this public repository. Passing source tests does not establish improved
profitability or successful future model serialization. Installation and natural
post-reopen cycle proof must be recorded separately in the operational review.

Rollback: restore the preceding scoped profile revision through the supported
profile updater, preserving the verified runtime/configuration checkpoint. Never
reset learning, account state or native orders to roll back these source changes.
